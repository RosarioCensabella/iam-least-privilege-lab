\# Detection Notes - IAM Least Privilege Lab



\## Objective



This document describes the detection logic for the IAM Least Privilege Lab.



The goal is to identify relevant security events generated by the lab, especially around:



\- IAM role assumption;

\- MFA-protected access;

\- denied access attempts;

\- S3 read-only access boundaries;

\- future S3 object-level monitoring.



\---



\## Detection Scope



The current lab focuses on the following AWS resources:



\- IAM user: `terraform-lab-admin`

\- IAM role: `novacloud-iam-lab-dev-data-analyst-readonly`

\- IAM policy: `novacloud-iam-lab-dev-data-analyst-s3-readonly`

\- S3 bucket: `novacloud-iam-lab-dev-606895006811`

\- IAM Access Analyzer: `novacloud-iam-lab-dev-access-analyzer`



\---



\## Available Detection Source



\### CloudTrail Event History



CloudTrail Event History was used to inspect recent management events.



In this checkpoint, the lab confirmed visibility for:



&#x20;   sts:AssumeRole



This is important because role assumption is the access boundary between the lab IAM user and the temporary data analyst role session.



\---



\## Management Events vs Data Events



CloudTrail has two important event categories for this lab.



\### Management Events



Management events include control-plane actions such as:



\- assuming a role;

\- creating IAM policies;

\- creating IAM roles;

\- modifying infrastructure;

\- calling Access Analyzer APIs.



Example:



&#x20;   sts:AssumeRole



These events are visible in CloudTrail Event History.



\### Data Events



Data events include object-level activity such as:



\- reading an S3 object;

\- uploading an S3 object;

\- deleting an S3 object.



Examples:



&#x20;   s3:GetObject

&#x20;   s3:PutObject

&#x20;   s3:DeleteObject



S3 object-level data events are not covered by the current basic Event History review. They require CloudTrail data event logging to be enabled.

\## Detection Use Case 1 - Monitor Role Assumption



\### Goal



Detect when the data analyst role is assumed.



\### Why It Matters



The role:



&#x20;   novacloud-iam-lab-dev-data-analyst-readonly



grants access to analytics reports. Even if the permissions are read-only, role assumption should still be monitored because it represents access to business data.



\### CloudTrail Event



&#x20;   sts:AssumeRole



\### AWS CLI Investigation Query



&#x20;   aws cloudtrail lookup-events `

&#x20;     --lookup-attributes AttributeKey=EventName,AttributeValue=AssumeRole `

&#x20;     --max-results 50 `

&#x20;     --profile iam-lab `

&#x20;     --query "Events\[?contains(CloudTrailEvent, 'novacloud-iam-lab-dev-data-analyst-readonly')].{Time:EventTime,EventId:EventId,Source:EventSource,Username:Username}" `

&#x20;     --output table



\### Expected Result



The query should return `AssumeRole` events generated by:



&#x20;   terraform-lab-admin



for the data analyst role.



\### Detection Logic



Alert or investigate when:



\- the role is assumed by an unexpected principal;

\- the role is assumed at unusual times;

\- the session name is suspicious or inconsistent;

\- repeated failed assume-role attempts occur;

\- role assumption happens without expected MFA context.



\---



\## Detection Use Case 2 - Detect Failed Role Assumption Without MFA



\### Goal



Detect attempts to assume the data analyst role without MFA.



\### Why It Matters



The trust policy requires MFA using:



&#x20;   aws:MultiFactorAuthPresent = true



A failed role assumption without MFA may indicate:



\- misuse of long-term access keys;

\- automation that does not comply with the MFA requirement;

\- a possible credential compromise attempt.



\### Relevant Event



&#x20;   sts:AssumeRole



\### Expected Error



&#x20;   AccessDenied



\### Detection Logic



Investigate `AssumeRole` failures where:



\- the target role is `novacloud-iam-lab-dev-data-analyst-readonly`;

\- the error is `AccessDenied`;

\- the request does not include a valid MFA context.

\## Detection Use Case 3 - Detect S3 Access Denied Attempts



\### Goal



Detect attempts by the data analyst role to perform actions outside its least privilege scope.



\### Why It Matters



The role is allowed to read only:



&#x20;   reports/\*



The role must not access:



&#x20;   evidence/\*



The role must not perform:



&#x20;   s3:PutObject

&#x20;   s3:DeleteObject



\### Observed During Manual Tests



The following denied actions were successfully tested:



\- listing the bucket root;

\- reading `evidence/internal-evidence.txt`;

\- uploading `reports/unauthorized-upload.txt`;

\- deleting `reports/sample-report.txt`.



\### Detection Logic



Investigate access denied events involving:



\- `s3:ListBucket` on the bucket root;

\- `s3:GetObject` outside `reports/\*`;

\- `s3:PutObject`;

\- `s3:DeleteObject`.



\### Current Limitation



This lab has not yet enabled CloudTrail S3 data events.



Therefore, object-level events such as `GetObject`, `PutObject`, and `DeleteObject` are not yet collected as CloudTrail data events.

\## Detection Use Case 4 - Monitor IAM Policy Changes



\### Goal



Detect changes to the IAM policy attached to the data analyst role.



\### Why It Matters



The policy is the core least privilege control. If someone modifies it to allow broader permissions, the security model is weakened.



\### Sensitive Policy



&#x20;   novacloud-iam-lab-dev-data-analyst-s3-readonly



\### Sensitive Role



&#x20;   novacloud-iam-lab-dev-data-analyst-readonly



\### Events to Monitor



&#x20;   CreatePolicyVersion

&#x20;   SetDefaultPolicyVersion

&#x20;   DeletePolicyVersion

&#x20;   AttachRolePolicy

&#x20;   DetachRolePolicy

&#x20;   PutRolePolicy

&#x20;   DeleteRolePolicy

&#x20;   UpdateAssumeRolePolicy



\### Detection Logic



Alert when:



\- a new policy version is created;

\- the default policy version changes;

\- a broad AWS managed policy is attached to the role;

\- the trust policy is modified;

\- MFA conditions are removed from the trust policy.

\## SIEM-Style Detection Ideas



The following detection ideas can be translated into SIEM rules.



\### Rule 1 - Sensitive Role Assumed



Trigger when:



&#x20;   eventName = AssumeRole

&#x20;   requestParameters.roleArn contains novacloud-iam-lab-dev-data-analyst-readonly



Severity:



&#x20;   Medium



Reason:



&#x20;   The data analyst role grants access to analytics reports.



\---



\### Rule 2 - Sensitive Role Assumption Failed



Trigger when:



&#x20;   eventName = AssumeRole

&#x20;   errorCode = AccessDenied

&#x20;   requestParameters.roleArn contains novacloud-iam-lab-dev-data-analyst-readonly



Severity:



&#x20;   Medium to High



Reason:



&#x20;   Failed role assumption could indicate misuse or credential compromise.



\---



\### Rule 3 - Data Analyst Role Attempts Write or Delete



Trigger when:



&#x20;   userIdentity.arn contains assumed-role/novacloud-iam-lab-dev-data-analyst-readonly

&#x20;   eventName in PutObject, DeleteObject



Severity:



&#x20;   High



Reason:



&#x20;   The role is designed to be read-only. Write or delete attempts should be investigated.



Current requirement:



&#x20;   Requires CloudTrail S3 data events.



\---



\### Rule 4 - Data Analyst Role Accesses Unauthorized Prefix



Trigger when:



&#x20;   userIdentity.arn contains assumed-role/novacloud-iam-lab-dev-data-analyst-readonly

&#x20;   requestParameters.key starts with evidence/



Severity:



&#x20;   High



Reason:



&#x20;   The role should only access reports/\*.



Current requirement:



&#x20;   Requires CloudTrail S3 data events.



\---



\### Rule 5 - Trust Policy Modified



Trigger when:



&#x20;   eventName = UpdateAssumeRolePolicy

&#x20;   requestParameters.roleName = novacloud-iam-lab-dev-data-analyst-readonly



Severity:



&#x20;   High



Reason:



&#x20;   Changes to the trust policy could weaken the MFA requirement or allow unexpected principals.
